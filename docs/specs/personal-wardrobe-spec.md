# Wardrowbe 个人化定制 Spec

> 状态：**草案，待审改**。来源：/grill-me 对话共识（2026-10-02）。
> 词表内容单独在 [vocabulary.md](./vocabulary.md)，直接在那份文档里改。
> 本文只描述"改什么、边界在哪"，不规定具体实现代码。

## 0. 定位与策略

- **单人自用**的本地衣橱工具：**整理（入库）· 记录（穿搭日志）· 浏览（查看/编辑）** 三大功能。
- **私有 fork，就地改造本 repo**，不考虑与上游合并；不开新项目。
- 不做：AI 每日穿搭推荐（现有 suggest **休眠**——不进导航，代码不删）。
- 产品壳（家庭/通知/学习/洗衣/多语言）**摘不删**：从导航、路由、菜单摘掉，代码与表结构保留。分析统计**部分保留**（见 §4 统计页、§7）。
- UI 语言 **zh-CN**；t() 管线保留，i18n 校验范围放宽（只保 zh-CN，en 可留作键源，其余语言文件冻结或移出校验）。
- 规模：衣物 **千件内**；每件 1 主图 + 可补细节图；一条记录 对应>=1 张穿搭照 + 任意件衣物（允许先存记录后补关联）；记录频率一周几次或偶尔。

## 1. 整理功能（拍照 → 入库）

### 1.1 上传

- 桌面网页上传（使用节奏：手机拍完传到电脑再整理；**不做移动端适配优化**）。
- 沿用现有上传管线：批量上传、HEIC 转换、pHash 去重、断点续传队列、三档尺寸（缩略/中/大）。

### 1.2 校色（灰卡 / 白纸）

- 参考物：**灰卡优先，白纸 fallback**（手头没有灰卡时放一张白纸即可）；两者都没有 → 跳过自动校色。
- 流程（灰卡与白纸一致）：**自动检出参考物区域 → 用户可手改框选范围** → 以框内像素作白平衡基准计算 → 应用到整图。
  - 自动检出顺序：先找灰卡，找不到再找白纸；检出结果（参考物类型 + 框）可手改——改框，或把类型从灰卡改成白纸（反之亦然）。
  - 基准差异：灰卡按**中性灰**基准；白纸按**纯白**基准（框内平均色对到白点）。
- 无参考物的照片：**跳过自动校色**（不猜白平衡），详情页提供**手动白平衡**：色温/色调滑块 + 重算。
- 校色结果可重置回原图（原图永远保留）。

### 1.3 抠图与手动修改

- **手动触发**（单品或批量），不自动入队。
- 输出 **透明 PNG** 作为存储形态；纯色底合成仅为可选展示样式，不作为存储。
- **mask 持久化**：保存后可再次进入编辑；画笔加/减 mask（补抠、擦多余）；可还原原图重抠。
- 沿用现有 rembg/u2net 本地抠图与原图备份/还原机制，去掉"合成到纯色底"的默认行为。

### 1.4 AI 打标签

- 输入：**校色后的像素**（建议用抠图结果合成白底的图做颜色判断，避免背景污染）。
- 时序：校色 → 抠图 → 打标签；打标签可随时重跑（沿用 re-analyze）。
- 输出为**闭集强制选择**（从词表候选里选，不允许自由发挥命名）：
  - 风格：多选（可空缺）；选择器内除现有标签外有「**添加**」按钮可当场新建
  - 类型：部位 → 类别 两级单选（如 上衣-背心）；选择器同样有「**添加**」按钮
  - 颜色：**主色多选 + 辅色多选（可空）**，具体色名两级（色系自动推导，如 绿色系-军绿）；选择器同样有「**添加**」按钮
  - 季节：多选（春/夏/秋/冬/四季）——AI 打 + 手改，**不由温度推导**
  - 温度：适用温度上下限（自由数值）
  - 材质、正式度：沿用现有词表
  - 备注：即目前的subtype，自由文本，可空缺
- 模型端点/模型/key **可配置**：测试阶段接云端视觉 API，跑通后切本地 **Qwen3 27B 多模态 Q4_M**（OpenAI 兼容端点）。不固定供应商。
- 人工可改一切标签；`tagged_by` 区分自动/手动（沿用现有）。

### 1.5 存档字段（衣物）

沿用现有字段 + 以下变更：

| 字段 | 变更 |
|------|------|
| `type` | 语义不变（类别 slug），值域换新词表 |
| `subtype`（备注） | 自由文本、可空；UI 显示名改「**备注**」（原"细分/子类型"），列名沿用 `subtype` 不迁移 |
| `body_part`（部位） | 由词表映射推导；**冗余存一列**便于筛选 |
| `primary_colors[]` | **新增**，主色多选（slug） |
| `secondary_colors[]` | **新增**，辅色多选、可空（slug）；替代原 `colors` |
| `primary_color` / `colors` | 被上面两列替代（迁移：原 primary → primary_colors，原 colors → secondary_colors） |
| `temp_low` / `temp_high` | **新增**，自由数值、可空 |
| `season[]` | 不变（多选） |
| `style`（风格） | **复用现有列**（ARRAY），多选、可空；**值域换新词表**（无旧数据，旧 12 风格值不迁移）；值来自风格标签（词表种子 + UI「添加」新建） |
| 状态（**三态**） | 新列 `lifecycle`：`active`=**在役**（默认）/ `idle`=**闲置** / `retired`=**已退役**；`is_archived` 保留为兼容视图（= retired）。`archive_reason`=退役原因（可选，仅退役）、`archived_at`=退役时间（自动）。网格默认隐藏**已退役**（**闲置默认可见**，带角标），筛「已退役」可查看 |
| `purchase_price`（价格） | **复用现有列**，自由数字、**可空**（不设档位，可用于统计） |
| `purchase_date`（购买时间） | **复用现有列**（Date，存当月代表日）；应用层精度 **年-月**（可只填年、不存日）、**可空**；默认 = **录入日的年月**，可改可清 |
| `wear_count` | 沿用，语义升级为**随记录自动累计**、可手改，手改后有新纪录则基于手改值继续自动累计 |
| 图片 | 1 主图（透明 PNG）+ 细节图（沿用 ItemImage）；mask 与校色前原图另存可还原 |

## 2. 词表体系

- **单一数据文件**（`backend/app/data/garment_vocabulary.json`）收敛：风格、两级类型、两级颜色、季节、洗护/正式度。
- 前端选择器与打标签提示词均从词表**运行时取用**（接口拉取 / 渲染），不再各存一份（消灭现有颜色双列表漂移）；gen 管线降为类型生成 + CI 校验。
- **风格/颜色/类型**为软词表：选择器带「添加/改名/停用」入口（见 §10.9）；改动**写回 JSON 并同步 vocabulary.md 对应表格行**——文档始终是唯一编辑面，重新编译不丢运行时新增；**保存即生效**（前端运行时拉词表）。
- 内容以 [vocabulary.md](./vocabulary.md) 为准（**用户手改那份文档**）。
- 值形态：英文 slug + 中文显示名同在词表文件里；UI 显示中文。
- **排序**：部位按固定逻辑序（上衣→下装→连衣裙/套装→外套→鞋袜→配饰→首饰）；部位内类别按**中文名拼音**，**兜底（其他xx）垫底**；色系按固定色序（黑白灰→棕→红→橙黄→绿→蓝→紫→粉→金属）；**风格按中文名拼音**。色系内部正X 第一、其余渐变（黑白灰/金属内部保持表序）。文档与 UI 同序；新加入的插对应位置（类别插拼音位但不越过兜底，颜色插渐变位，风格插拼音位）。

## 3. 记录功能（穿搭日志）

### 3.1 创建记录

- 入口：上传穿搭照 → 建记录。**一条记录 1..N 张照片**（新增 outfit_photos，走同一图片处理管线）。
- 记录字段：
  - **日期**：默认今天、可改
  - **季节**：按记录日期**自动推导**（3-5月春 / 6-9月夏 / 10-11月秋 / 12-2月冬），可手改
  - **城市**：记录级字段；预设 **杭州/香港/合肥/深圳**（设置里可扩展、可设默认城市）；**可留空**
  - **天气/温度**：有城市则自动取当天天气**预填，可改可清**（过去日期拉历史天气，见 §10.16）；无城市则手动填或留空
  - **关联衣物**：任意件（含 0），允许先存记录后补关联
  - 备注/场合：沿用现有可选字段，不新增
- 同一天允许多条记录；一件衣物可出现在多条记录。

### 3.2 衣物关联

- **手动关联为主路径**：从归档库勾选（沿用 studio/OutfitItem 机制）。
- **AI 建议关联**（可选按钮，排 **M2**——可并入 M1 或紧随，不阻塞手动流程）：
  - 架构：**两阶段**——(1) embedding 对穿搭照衣物区域与归档图做检索，召回 top 10-20；(2) 视觉模型在小集合内验证/重排。
  - **向量一次性**：归档衣物的 embedding **入库时算一次、存库**；点「AI 建议」只现算穿搭照侧的 query 向量，和库存向量比对，**不重算全库**。重算仅两种时机：该件归档图变更（重抠/校色重做/换图）→ 重建该件；换 embedding 模型 → 批量全库重建（留重建入口）。
  - 产出 **5-8 个候选缩略图**，用户点选确认；**绝不自动入库**。
  - 降级：embedding/模型不可用时按钮置灰或隐藏，手动关联不受影响。

## 4. 浏览与编辑

- **衣物**：网格 + 筛选（部位/类别/色系/具体色/风格/季节/状态）+ 文本搜索；"已退役"的衣物**默认不进网格**（沿用现有接口默认），筛「已退役」可查看、卡片标注"已退役"；详情页可编辑一切标签、图片、校色/mask 重编辑、白平衡。
- **衣物详情页新增**：
  - **穿了几次**：显示 wear_count，可手改；记录创建/编辑关联时自动 ±；手改后新的记录在**手改值基础上**继续累计
  - **反查**：该衣物关联的全部记录（日期倒序）
  - **常搭衣物**：与该衣物共现次数 top N（全历史，先不做时间窗）
- **记录**：时间线 + 月历（复用现有组件）；详情/编辑：照片、关联衣物、日期、季节、城市/天气、备注。
- **统计页**（原 analytics 就地瘦身，导航名「统计」）：
  - 保留：总览（衣物总数/管线状态分布/记录数/本周本月/总穿着次数）、颜色分布、类型分布、**风格分布**、穿最多/最少/从没穿排名
  - 摘：AI 指标（接受率/评分均值/接受趋势）、insights 搭配建议
  - 口径：**默认全算（含已退役）**，带「含已退役」开关可切仅在役
  - 价格本期不进统计（字段可用，以后再汇总）

## 5. 数据模型变更汇总

- `clothing_items`：+ `body_part`、`primary_colors[]`、`secondary_colors[]`、`temp_low`、`temp_high`；**复用现有列** `style`（值域换新词表）、`purchase_price`（=价格）、`purchase_date`（=购买时间，年-月精度）；**状态三态**：新列 `lifecycle`（`item_lifecycle` 枚举：active/idle/retired），`is_archived` 保留为退役兼容视图 + `archive_reason`/`archived_at`（旧数据迁移：is_archived=True→retired、False→active）；− `primary_color`、`colors`（迁移见 §1.5）；`subtype` 列保留（UI 语义 = 备注）
- 新表 `outfit_photos`（outfit_id, 排序, 图片路径三档）
- `outfits`：+ `city`（可空）；`season` 语义改为"按日期推导、可手改"；日期沿用现有 `scheduled_for`；`occasion` 现为 NOT NULL——迁移放宽可空（或存空串，实现时定）
- 沿用不动：`item_images`、`item_history`（**反查**的数据源，记录关联时照旧写入）、`outfit_items`；**穿了几次以 `wear_count` 列为准**（item_history 只做记录明细，不做计数源）
- Alembic 迁移，迁移时把旧颜色数据转新列

## 6. AI 配置

- 环境变量保留：`AI_BASE_URL` / `AI_API_KEY` / `AI_VISION_MODEL` / `AI_TEXT_MODEL` 等；设置页可暴露为可配置项（"反正要留设置"——落 env 还是落设置页 UI，实现时定，两者皆可）。
- 测试阶段接云端视觉端点（供应商不固定），验证流程后切本地 Qwen3 27B 多模态 Q4_M。
- 打标签与 AI 建议关联共用视觉端点配置；AI 建议关联的 embedding 模型单独配置（本地 embedding 服务或 API）；衣物向量入库只算一次，换模型需批量重建（见 §3.2）。

## 7. 裁剪清单（摘不删）

| 模块 | 处置 |
|------|------|
| 家庭/多用户（families, invites, 家庭评分） | 摘：导航/入口去掉，后端路由关闭或不挂 |
| 通知推送（ntfy/Mattermost/SMTP、定时任务） | 摘 |
| 分析统计 | **部分保留**：摘 AI 指标与 insights，保留总览/分布/穿着排名（见 §4 统计页） |
| 学习反馈（learning） | 摘 |
| 洗衣跟踪（wash） | 摘（**穿了几次保留**，这是两回事） |
| AI 推荐（suggest/pairings） | **休眠**：不进导航 |
| 多语言 | UI 锁 zh-CN；i18n 校验放宽；其余语言文件冻结 |
| 登录 | dev 模式单用户（`DEBUG=true`） |

保留：衣物、记录、设置（AI/城市）、图片管线、词表管线、历史日历组件。

## 8. 部署

- docker compose：Postgres + Redis + backend + frontend + 2 个 worker（AI/图片），dev 模式单用户登录。
- 图片存储走现有 volume（`storage_path`）；备份 = 卷 + 数据库 dump。
- 词表 JSON 运行时可写、**随数据持久**（挂 volume 或进备份清单），否则 UI 增改重启即丢。

## 9. 分期建议

- **M1（主线）**：词表改造 + schema 迁移 + 校色 + mask 编辑 + 打标签闭集化 + 记录（多照片/手动关联/日期/季节/城市/天气）+ 浏览编辑 + 穿了几次/反查/常搭 + 统计页瘦身 + 裁剪 + zh-CN。
- **M2（可并入 M1 或紧随）**：AI 建议关联（两阶段，可选按钮，可降级）。

## 10. 已声明的解读与默认（有异议请改这里）

1. 「季节按日期自动推导」落为：**记录**的季节按日期推导；**衣物**的季节 = AI 打 + 手改（不由温度推导）。
2. 主色、辅色均多选；不设硬上限（UI 上建议主色 1-2、辅色 0-6，可存更多）。
3. 校色参考物 = 灰卡 → 白纸 fallback，两者都没有跳过自动校色（不做 AI 猜色）。自动检出先找灰卡再找白纸，检出的类型与框都可手改。白纸作参考时框内平均色对到纯白。
4. AI 建议关联永不自动入库，只做候选辅助。
5. 常搭衣物 = 全历史共现 top N。
6. 城市列表初始为杭州/香港/合肥/深圳，存在设置里（非词表）。
7. 「状态」= 在役 / 已退役，默认**在役**；网格**默认只显示在役**（沿用现有接口默认），筛「已退役」可查看、卡片标注"已退役"；历史记录/反查/穿了几次照常保留（不抹历史）。
8. 「价格」按人民币展示、**不存币种**；**可用于统计**（本期统计页不汇总价格）。
9. 「风格/颜色/类型」是软词表：UI 选择器有「**添加**」按钮，另有**改名/停用**（停用不进选择器、历史照常显示；**不物理删除、不合并**）；新增**写回 `garment_vocabulary.json` 成为正式成员**；AI 打标签从当前列表闭集选。类型只能在现有 7 部位下加类别（新部位不开放）；颜色可加**新色系/新具体色**，**hex 必选**、UI 带色板直观预览（色名/色块在选择器里同显）；材质/正式度不开放添加。
10. 「备注」= 现有 `subtype`，仅 UI 改名，列名沿用不做迁移。
11. 风格分布按**标签计次**（一件多风格在多个条形各计 1，口径标注"件次"）。
12. 词表 UI 增改：**改名只改中文名不改 slug**；**停用 = 条目标记**（不进选择器、历史照常显示）；写回 JSON 与 vocabulary.md 同步（见 §2）。
13. 词表排序：部位=固定逻辑序（上衣→下装→连衣裙/套装→外套→鞋袜→配饰→首饰）；部位内类别=拼音、兜底垫底；色系=固定色序（黑白灰→棕→红→橙黄→绿→蓝→紫→粉→金属）；风格=拼音。色系内部=正X+渐变（黑白灰/金属内部保持表序）。
14. 「购买时间」精度只有 **年** 或 **年-月** 两档（不存日）；默认取**录入年月**，可置空。
15. 颜色分布按**主色件次**统计（一件多主色在多条各计 1，**辅色不计**）；类型分布按件数。
16. 天气预填：过去日期也**拉历史天气**（接口可得就拉，如 Open-Meteo archive）；拉不到才留空手填。

16. **状态三态**：在役/闲置/已退役（`lifecycle` 枚举）；闲置默认可见、已退役默认隐藏；统计三档口径：全部 / 排除退役（在役+闲置）/ 仅在役，默认全部。
17. **软词表写回细节**：禁用标记 = vocabulary.md 行尾「已停用」+ JSON `"disabled": true`（恢复即两处撤销）；新条目插入位见 vocabulary.md 头部约定（类别/风格=拼音位，颜色=渐变位）；运行时新增类型的 role/wash_interval 按部位推导（`ROLE_BY_PART`/`WASH_BY_PART`）。
18. **词表进程内快照**：backend/worker 的 AI 校验集与提示词在进程启动时快照，运行时增改**重启容器后**对打标签生效（前端选择器即时生效）。
19. **词表写回单写者**：JSON+markdown 写回在单 uvicorn 进程内加锁串行，JSON 面原子写（临时文件+rename）；多 worker 部署需换文件锁，本项目按单进程不变量运行。
20. **部署面**：本项目是单机本地工具，只维护 `docker-compose.yml`(+`.dev`)；上游 `docker-compose.prod.yml`（生产/Pi 变体）按摘不删下线。
